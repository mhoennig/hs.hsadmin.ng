# PR#313: Monitoring-Endpoint für den Import des Bankenverzeichnisses

## Das Problem

Der Import der Bundesbank-Datei aus [PR#307](2026-09-24-PR%23307-bank-codes-import.md) läuft unbeaufsichtigt;
scheitert er dauerhaft, steht dies infolgedessen nur im Log, und das Bankenverzeichnis veraltet unbemerkt.
Ein externes Monitoring braucht dafür eine Abfrage ohne Zugangsdaten,
wie `GET /api/rbac/subjects/last-sync` für den Subject-Sync.

Die Bundesbank veröffentlicht nur vierteljährlich eine neue Version;
am Alter des letzten Imports allein erkennt ein Monitoring einen Ausfall darum derzeit erst nach Monaten.

## Nicht-Ziele

- Keine detaillierten Fehlermeldungen im Endpoint; sie können interne Details enthalten und bleiben daher nur im Log.
- Kein Schwellwert im Backend, ab wann der Import zu alt ist; den legt das Monitoring fest.

## Die Lösung

- `hs_office.bank_directory_import` aus PR#307 hält nun jeden Versuch, auch unveränderte und Wiederholungen;
  diese löscht der Importer nach einem Jahr, importierte Versionen bleiben.
- Ein Fehlschlag speichert nur seine Art (`HTTP_ERROR`, `NO_RESPONSE`, `INVALID_FILE`, `INTERNAL`),
  den Request an die Bundesbank, deren HTTP-Status oder die fehlerhafte Zeile der Datei.
- `GET /api/hs/office/bank-directory/import-status` zeigt die aktive Version, den letzten erfolgreichen Versuch
  und die jüngsten Versuche; er ist öffentlich, da er weder Bankkonten noch Fehlermeldungen zeigt.
- `validSepaMandatesWithIssues` zählt die SEPA-Mandate, die `GET /api/hs/office/sepamandates?issues=true` aus PR#311 liefert,
  über die Schnittstelle `HsOfficeBankDirectoryController.SepaMandateIssues`,
  denn das Paket `bankaccount` darf die SEPA-Mandate nicht kennen.
- `tools/monitoring-check` meldet einen Alarm, wenn seit `HSADMINNG_MONITORING_BANK_DIRECTORY_MAX_RUN_AGE_DAYS`
  (Vorgabe 8 Tage) kein Importversuch erfolgreich war;
  so fällt ein Ausfall wie in Scenario#313.02 etwa einen Tag nach dem ersten gescheiterten wöchentlichen Versuch auf.
- Er meldet auch einen Alarm, wenn das Bankenverzeichnis älter ist als `HSADMINNG_MONITORING_BANK_DIRECTORY_MAX_AGE_DAYS`
  (Vorgabe 100 Tage, also ein Quartal mit Puffer); dies erkennt Versuche, die zwar gelingen, aber keine neue Version finden.
- SEPA-Mandate mit Issues zeigt der Check nur an und löst keinen Alarm aus:
  die Verwaltung muss sie bis zum nächsten Einzug korrigieren, nicht binnen Minuten,
  und ein Alarm alle paar Stunden bis dahin würde echte Ausfälle überdecken.

## Zusätzliche Änderungen

- Szenarien können mit `ExternalSystem.Stub.fails(...)` ein externes System mit einem Fehlerstatus antworten lassen.
- Das Monitoring prüft nicht mehr nur den Login, sondern auch den Bankenverzeichnis-Import-Status;
  daher heißen `tools/login-monitoring-check` nun `tools/monitoring-check`,
  `remote login-monitor` nun `remote monitoring` und die Variablen `HSADMINNG_LOGIN_MONITOR_*` nun `HSADMINNG_MONITORING_*`;
  `remote monitoring deploy` entfernt den alten Timer auf dev und int.
- In den HTML-Szenario-Reports führen die Links auf vorausgesetzte Szenarien nun auf deren `.html`-Report statt ins Leere.

## Release Note

released: 2026-10-01

### The bank-directory import can be monitored

Since 2026-10-01, `GET /api/hs/office/bank-directory/import-status` returns the current bank-directory version,
the last successful import attempt, the recent attempts including the Bundesbank's answer to failed ones
and the number of valid SEPA mandates whose bank account does not match the bank directory, without authentication.
The monitoring alerts if no bank-directory import run succeeded within 8 days or if the bank directory is older than 100 days.
